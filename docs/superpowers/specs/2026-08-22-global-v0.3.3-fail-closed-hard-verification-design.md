# Global v0.3.3 Fail-Closed Hard Verification Design

## Goal

Upgrade `heymio/gtm-listing-demo` from v0.3.2 to v0.3.3 by importing the generic hard-verification improvements proven in `japan-listing-demo` v0.3.3, while preserving Global market/locale/region/channel/category/profile architecture and excluding Japan-specific marketplace/localization policy.

## Non-goals

Do not import Amazon.co.jp-specific module ceilings, ja-JP copy rules, Japan consumer assumptions, Japan legal/claim policy, product-specific fixtures, private account capability values, or Japan-only channel behavior.

## Required generic changes

1. Fail-closed Demo hardening: Delivery State 0.2 cannot disable mandatory pre-Demo verification; required asset set must be non-empty.
2. Required asset union: derive required IDs from locked plan, implementation, slot contracts, explicit required IDs, Production blocker/revision state, and Production handoff page-plan/asset-set sources as applicable.
3. Production Freeze v0.3.3: exact `asset_id -> candidate_id -> output_ref`, no blockers/revisions, fresh Set QA, `ready_for_hardening=true`; Hardening recomputes readiness.
4. Canonical executable `FRONTEND_FIDELITY_GATE` and `DEMO_RUNTIME_GATE`.
5. Real file verification: complete PNG/JPEG/WebP validation plus Pillow decode/load; no decoder means no hard PASS.
6. `PROOF_VISUAL` claim/fact/authoritative-source binding plus trusted claim review requirement.
7. Standalone Demo: static preflight rejects all external/local/SVG/style dependencies but static wiring is not runtime PASS.
8. Browser runtime: Playwright/Chromium, zero network, exact Demo SHA, 1440px + 390px, overflow/broken/clipping checks, actual carousel next/prev behavior when present.
9. Distribution: deterministic ZIPs, symlink rejection, extracted package validation, reproducibility checks.
10. Release: exact-main-SHA self-validation in read-only build job; publish job has write permission only, no repo checkout/code execution, explicit repository target, safe absent-tag handling, checksum verification.
11. UX semantics: ambiguous pause wording must not advance major stages; current-asset acceptance remains local to Production.

## Global invariants

- Channel module budgets come from current site/account capability profiles, never a Japan hardcoded limit.
- `market`, `locale`, `region`, `channel`, `site`, `category`, and account capability remain Global profile/context inputs.
- Existing Global profile mirror-consistency regressions remain green.
- Static pages without carousel remain valid; carousel runtime checks apply only when carousel is present.
- Release publication is optional infrastructure; it must not alter workflow semantics.

## Acceptance

A candidate is merge-ready only when:

- all existing v0.3.2 Global regressions pass;
- ported v0.3.3 adversarial regressions pass;
- real Pillow and Chromium regressions pass in CI;
- both package modes build twice to identical SHA-256 and validate after extraction;
- symlink escape regression passes;
- Japan/product/site-specific leakage checks remain zero;
- Draft PR remains unmerged until explicit user confirmation.
