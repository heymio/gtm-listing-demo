# v0.3.2 Global Production and Demo regression scenarios

## Complete set vs priority proof

A page plan contains eight final visual roles, while only three P0 proof images currently exist. Expected: Planning keeps the complete eight-asset Demo-required set; P0 coverage does not complete Stage 7/8.

## Candidate Selection Lock

The user selects `G2-v2`, then asks to continue to the next asset. Expected: `G2-v2` remains the selected exact output; Production does not create `G2-v3`, replace its output ref, or roll G2 back to review without explicit reopen intent.

## Creative Mock with missing proof

A lifestyle scene has a verified real product identity source but a proof-grade installation reference is missing. Expected: `CREATIVE_MOCK` may proceed as `READY_WITH_LIMITATION`; generated installation/context details do not become Product Truth. If the product identity source itself is missing, production blocks.

## Repetitive visual set

Three adjacent assets reuse the same scene/composition/tone/scale/proof form. Expected: set-level QA flags the repetition and applies the smallest sufficient cleanup rather than regenerating the entire approved set.

## Exact-output set QA invalidation

A whole-set contact sheet was reviewed with `A1-v1`; A1 is later explicitly reopened and `A1-v2` is selected. Expected: the old whole-set QA becomes stale until the current exact output set is reviewed together again.

## Scope change

The user removes one already planned asset. Expected: removal updates the authoritative asset set, page order, and Page Visual System together without reopening unrelated approved assets. Adding a new asset or changing role/message/evidence requirements returns to Planning.

## Exact-file replacement

An approved filename is overwritten with different bytes. Expected: Evidence Auditor recomputes the hash and the new bytes do not inherit prior exact approval.

## Native shell without frontend evidence

Platform documentation confirms a capability family but no current consumer-facing reference is available. Expected: native frontend fidelity remains unverified and the workflow uses a Content Review Demo rather than inventing shell details.

## Standalone static Demo

A DTC/retailer page is intentionally static with no carousel. Expected: the one-file standalone validator passes when all resources are embedded and responsive requirements are met; it does not invent a carousel requirement.

## Broken portable dependency

A final HTML uses an adjacent image, mixed external `srcset`, or literal session-only `blob:` resource. Expected: static Demo validation fails before delivery.

## Mobile runtime unavailable

The exact final HTML passes static checks but no browser/runtime execution is available. Expected: desktop/mobile interaction QA remains `BLOCKED`; source inspection alone cannot claim PASS.

## Cross-market isolation

The same core runs for multiple market/locale/channel combinations. Expected: channel/site/account rules come from selected current profiles/capability evidence; no consumer preference, product fact, or marketplace-specific module ceiling leaks into generic defaults.
