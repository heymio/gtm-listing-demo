# Localization reference

## Separate market from locale

- `market` identifies the target country or commercial market.
- `locale` controls language and deterministic formatting rules.
- `region_overlays` add cross-country checks.
- `category` and project evidence determine product-specific needs and scenarios.

A locale profile must not state that consumers in that locale prefer a feature, scene, or message hierarchy without project evidence.

## Output language

- Internal analysis follows the user's working language unless requested otherwise.
- Consumer-facing copy follows the selected locale.
- Source quotations retain their source language.
- Cross-market comparisons use the analysis language selected by the user.

## Locale profile scope

A locale profile may define:

- language and script
- punctuation and spacing
- capitalization
- date and time format
- decimal and thousands separators
- currency display
- unit presentation
- title and copy-length constraints
- search-language targets
- native copy review requirements

It may not define:

- target persona
- product priorities
- category JTBD
- purchase motivation
- preferred feature order
- residential or lifestyle scenarios

## Localization ladder

1. Accurate translation
2. Locale-correct formatting
3. Channel-appropriate copy
4. Market evidence alignment
5. Native review
6. Claim and compliance review

Translation alone does not complete localization.

## Search language

Keyword research must use the combination of category, locale, market, and channel. A generic country profile cannot provide a permanent keyword list.

## Multi-locale projects

Create separate locale outputs when language, formatting, search behavior, or channel constraints differ. Region overlays do not replace locale-specific review.
