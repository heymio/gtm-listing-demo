# Frontend fidelity

Lock a current Primary Reference / frontend visual reference for channel-native Demo work. Platform documentation and capability evidence may prove support, but they do not substitute for current consumer-facing visual evidence.

## `CHANNEL_NATIVE`

To pass `FRONTEND_FIDELITY_GATE`, current evidence must support the claimed shell, section order, region distinctions, desktop structure, interaction behavior, and content regions. Mobile behavior must be known or explicitly scoped out, unsupported UI must not be fabricated, and the exact fidelity payload must have valid user approval provenance.

## `CONTENT_REVIEW`

When native fidelity cannot be supported, use a clearly labeled Content Review Demo. It must not claim channel-native fidelity and it still requires current evidence references plus exact approval for the fallback fidelity payload.

Missing/stale evidence or approval remains `UNVERIFIED` / `FAIL`. Do not invent channel chrome or turn a generic review layout into a native-fidelity PASS.
